## Part 1: Fixed both broken builds

- **Portal build broken**: `apps/portal/src/pages/auth/LoginPage.tsx` and
  `MyRequestPage.tsx` imported `../../lib/axios`, but `apps/portal/src/lib/axios.ts`
  was never created - only the admin app got one during the `2205261` migration.
  Created it, mirroring `apps/admin/src/lib/axios.ts`'s queued-refresh logic but
  pointed at `/applicant-auth/refresh`. Switched `useApplicantAuth.tsx` onto it and
  deleted both apps' now-orphaned `lib/api.ts`. See `technical/gotchas.md` #10.
- **Admin build also broken, previously undocumented**: `apps/admin/src/hooks/
useAuth.tsx` imported from a doubled `@/src/lib/axios` path (the `@` alias already
  resolves to `apps/admin/src`). Changed to the plain relative `../lib/axios`. See
  `technical/gotchas.md` #11.
- **Related bug found in the same investigation**: the `sessionStorage` key used for
  the "session expired, please log in again" message was written as `session_expired`
  (English, by `lib/axios.ts`'s refresh-failure redirect) but read as `session_expiree`
  (French) in admin's `LoginPage.tsx` - the two never matched, so the message never
  showed. Standardized on `session_expired` and added the matching read+clear check
  to portal's `LoginPage.tsx`, which had none at all. See `technical/gotchas.md` #12.
- `apps/portal/vite.config.ts` brought to parity with admin's: `@` alias, dev proxy
  to the API (`/api`, `/uploads`), explicit build output config

## Part 2 (same day): Sprint 2 - Phase Préliminaire (M3), full API + UI

With both builds fixed and pushed as `a4a5220`, continued into Sprint 2:

- **Phase lifecycle** (`modules/phases/`): open M3 on a request in `pending_review`
  (moves it to `in_progress`), close with a doc or note
- **Meetings** (`modules/meetings/`): schedule, status changes (`held`/`no_show`/
  `rescheduled`/`file_cancelled`, plus `scheduled` as the real initial status),
  reschedule. Hard conflict (same DN agent, exact slot) blocked by the existing DB
  constraint; same-day soft overlap is a non-blocking warning. Tickets are
  server-rendered HTML (`GET /api/meetings/:id/ticket`), not a generated PDF - a
  deliberate scope call, see `project/decisions.md` #12
- **Preliminary evaluation declaration** (`modules/preliminary-evaluation/`): made
  available post-meeting, portal upload of the filled form, dynamic return delay
  (`system_parameters`, default 15 days)
- **New module, generalized ahead of M4 on request**: `document_templates` - DN
  uploads/replaces blank forms by key, versioned via the M8 pattern. 4 keys seeded:
  the M3 declaration (in use) plus 3 M4 forms (schema-ready for Sprint 3). See
  `project/decisions.md` #11
- **Real security fix**: `authenticateEither` could let a stale staff session
  cookie win over a genuine applicant request, since admin/portal share a
  top-level domain and cookies aren't isolated between them. Now checks the
  cookie matching the request's `Origin` header first. See `technical/gotchas.md`
  #19 and `project/decisions.md` #13
- **6 real bugs found and fixed**: controllers crashing on an empty request body
  (systemic - hit Sprint 1 code too, not just new Sprint 2 code); a router-mount
  collision that silently blocked applicant access to `preliminary-evaluation`;
  check-ordering for a clearer double-open error; `packages/shared`'s
  `MEETING_STATUSES` missing the schema's actual `scheduled` default; a missing
  portal-facing bundle endpoint; missing imports caught immediately by typecheck.
  Full detail in `technical/gotchas.md` #15-#18
- Full admin UI (phase page, meeting scheduling/status/ticket, declaration
  tracking, document templates management) and portal UI (ticket view, blank form
  download, submission)

## Dev Reset Hardening

Existing `/api/dev-tools` support was extended rather than replaced.

New/changed behavior:

- `GET /api/dev-tools/status` now returns richer status metadata:
  - environment;
  - required access;
  - irreversible mode;
  - maintenance session state;
  - reset scope labels/descriptions/warnings.
- `POST /api/dev-tools/session` opens a temporary in-memory maintenance session.
- `POST /api/dev-tools/reset` now requires:
  - authenticated `SU`;
  - `ENABLE_DEV_RESET=true`;
  - production guard allowance when `NODE_ENV=production` or `APP_ENV=production`
    (`ALLOW_PRODUCTION_DEV_RESET=true`);
  - active maintenance session owned by the same SU actor;
  - exact confirmation text `NETTOYER`.
- Starting a maintenance session writes a `DEV_MAINTENANCE_SESSION_STARTED` audit trace.

The reset scopes remain deliberately explicit:

- `requests_and_workflow`;
- `organisations_and_applicants`;
- `notifications`;
- `audit_logs`;
- `reports`.

The reset still never offers staff users, roles, system parameters, or document templates as resettable scopes.

Follow-up issue found:

- `reports` scope deleted DB report rows but left generated report files under `apps/api/uploads/reports`.
- Some document template rows can reference upload URLs whose physical files are no longer present, causing dead `Voir le fichier actuel` links.

Correction made:

- `reports` dev-reset scope now deletes files in the protected generated reports folder before truncating `reports`.
- `requests_and_workflow` dev-reset scope now deletes physical files referenced by resettable `document_versions` owner types before truncating workflow data.
- Resettable upload asset metadata for workflow-owned uploads is deleted; `document_template` remains protected.
- Document template list API now reports `fileExists`.
- Admin document templates UI now shows a missing-file warning instead of a dead current-file link.
- New document template uploads now send `moduleHint=document-templates` and pass `uploadAssetId` to the template API so the upload asset is linked to `document_template`.

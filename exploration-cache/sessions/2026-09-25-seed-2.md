# Session 2026-09-25 - SEED-2 État du système

## Scope

SU-only « Paramètres → État du système »: observe reference data and core
services, and create missing reference data without restarting the API.
Startup seeding unchanged. UI never says "seed".

## Approved decisions

1. Inactive template: shown « Inactif - Réactivation manuelle requise. » No
   automatic reactivation; replacement does not reactivate.
2. One precedence everywhere (`classifyTemplateHealth`, `@aidn/shared`):
   no row -> missing; inactive -> inactive; storage unreachable -> unchecked;
   null/absent file -> file_missing; otherwise healthy. Modèles de documents
   page maps it to its own labels (`deriveTemplatePageStatus`).
3. Storage unreachable -> active templates `unchecked` (« Non vérifié »), never
   `file_missing`; missing rows still detected.
4. Storage check = `stat()` + `access(R_OK|W_OK)`; nothing is written.
5. Audit `REFERENCE_DATA_SEED_RUN` for successful manual runs only (including
   0 created); failures stay in server logs.
6. `UPLOADS_ROOT` for static serving, upload storage (+ orphan cleanup in the
   same service), template file checks, seeding and health. Remaining
   cwd-relative: dev-tools, reports, certificates (follow-up UPLOADS-ROOT).

## Design

- `seeding.health.ts`: `collectSystemStatus(probe)` - pure evaluation over an
  injected probe; `createDbSystemStatusProbe(db)`; `checkStorageRoot(dir)`.
  DB ping first; if it or a reference query fails -> `referenceData: null`.
- `seeding.service.ts`: `runSeeds(context)` (context only affects the template
  audit: `manual-run` + SU; uploader stays null); `runReferenceDataSeed(actor)`
  maps the result (no bundled file names) and audits after commit (audit failure
  logged, run still 200).
- `SeedingError.code` + `handleSeedingError`: LOCK_TIMEOUT -> 409, else 500
  with a generic message (details only in the log).
- Admin: query `staleTime: 0`, no focus refetch, no polling; run invalidates
  status + system parameters.

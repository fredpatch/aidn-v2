# Session 2026-09-25 - SEED-1B Official Document-Template Seeding

## Business Rule

Startup may create what never existed, but must never "correct" something DN
already owns. Any existing `document_templates` row for a key - whatever its
label, file, MIME type, active flag or physical-file state - is skipped.

## Design

- Paths resolve from the module location (`../../../..` = `apps/api`) - same
  layout in `src/` and `dist/`, same strategy as the uploads router.
- Storage follows the upload endpoint layout
  `YYYY/MM/DD/<source>/<moduleHint>/<file>` with source `api`, module hint
  `document-templates`, file `seed-<key>-<timestamp>-<random>.docx`.
- Records (template, current version, linked upload asset, audit row with
  `user_id = null`) are written through the SEED-1A advisory-lock transaction.
- File cleanup: immediate best-effort removal if record creation throws or the
  key was taken concurrently; `withSeededFileRollback` removes every file of the
  run if the transaction later rolls back. Cleanup failures are logged by
  storage key, never masking the original error.
- A missing bundled asset for a key that must be created fails the seed (and
  startup); an asset is not required for keys that already exist.
- CLI: `npm run seed` (all), `npm run seed:params` (parameters only).

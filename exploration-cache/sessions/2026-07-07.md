# Session - 2026-07-07

Single-day session covering the entire AIDN v2 rebuild kickoff: methodology,
scaffold, first real feature end-to-end, and a UI correction pass.

## Sprint 0 - Feasibility study, patterns, stack, scaffold, schema

- 13-module Q&A feasibility study against the CDC, mirroring SICOT's methodology -
  produced `project/overview.md`, `project/modules-feasibility.md`
- 6 cross-cutting patterns extracted (Circuit DG, Réunion/Visite, Clôture de phase,
  Facture/Preuve, Checklist documentaire, Une seule demande active) -
  `technical/cross-cutting-patterns.md`
- Notion dashboard + backlog + idées databases initialized, mirroring SICOT's
  project-tracking structure
- Database decision: PostgreSQL + Drizzle over the legacy's MongoDB (relational
  integrity fits the locked business rules better)
- Monorepo scaffolded (`apps/api|admin|portal`, `packages/shared`) - verified with
  real `npm install`, typecheck, build, and API boot at each step, not just written
- `technical/conventions.md` written - then corrected once for a language-policy
  change (English code / French UI, a deliberate divergence from SICOT)
- Full 20-table PostgreSQL schema written and verified with `drizzle-kit generate`
  producing real migration SQL, including the two DB-level constraints that
  actually enforce locked business rules (`requests_one_active_per_organisation_idx`,
  `meetings_dn_agent_slot_idx`)

## Sprint 1 - Intake & Circuit DG (M1+M2), full stack

- Auth/Users/Bootstrap prerequisite built first, mirroring SICOT's model (matricule
  - OTP first-login, bcrypt, JWT cookies) but adapted for multi-role via a
    `user_roles` join table instead of a single `role` column
- `system_parameters` table - SICOT's `parametres` equivalent
- M1 business logic: submit/sign/pending-review/cancel, DB-enforced one-active-
  request rule, `DEM-YYYY-MM-DD-ORGCODE-NN` reference generator, stuck-parapheur
  alert cron
- **Real gap, caught by Fred**: initial testing used a staff SU token standing in
  for an applicant - applicant auth didn't exist. Built `modules/applicant-auth/`
  with a `kind`-discriminated JWT so staff and applicant tokens can never be
  confused
- **Real gap, caught by Fred**: the admin/portal auth screens only reused SICOT's
  color tokens, not its actual component structure. Rebuilt Bootstrap/Login/Layout
  with the real design system (react-hook-form+zod, framer-motion, shadcn-style
  primitives), and added a Users management page in the process (needed to make
  the multi-role system usable via UI at all - wasn't originally scoped)
- Full cross-app flow verified against a real running Postgres instance: applicant
  logs in on the portal, uploads a file, submits a demande, gets correctly blocked
  on a duplicate attempt; staff (SU) sees the _same_ record, advances it through
  the circuit; applicant sees the updated status reflected back

## 10 real bugs found and fixed (full detail in `technical/gotchas.md`)

1. `ignoreDeprecations: "6.0"` invalid on the TypeScript version that actually
   resolves (copied verbatim from SICOT without checking)
2. `baseUrl` deprecation - fixed properly (removed + relative `paths`) instead of
   silencing the warning
3. **Confirmed upstream `drizzle-kit@0.31.10` bug**: the `migrate` CLI silently
   swallows real errors. Worked around with a programmatic migration script -
   this is how bugs #4 and #5 below were even diagnosable
4. Postgres enum-in-same-transaction error (`unsafe use of new value`)
5. Postgres `schema "public" does not exist`
6. Uploads endpoint had zero authentication despite a comment claiming otherwise
7. Applicant auth gap (see above)
8. Drizzle wraps pg errors - `error.cause.code`, not `error.code`
9. `@aidn/shared` needs a build step before its types resolve - automated via a
   root `postinstall` script
10. tsconfig files got mixed up during a manual local fix - caught by re-verifying
    rather than trusting a "fixed" report

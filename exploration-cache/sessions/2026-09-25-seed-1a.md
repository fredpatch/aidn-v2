# Session 2026-09-25 - SEED-1A Startup System-Parameter Seeding

## Purpose

Guarantee that every environment has the required `system_parameters` rows
without an operator remembering `npm run seed:params`. First slice of the
reference-data seeding track (SEED-1A -> 1B templates -> 1C fallback defaults).

## Decisions

- **Per-item idempotency, no completion flag.** Missing key -> created; existing
  key -> skipped and never modified (value, type, module, description). A new
  definition shipped later is created on the next startup everywhere.
- **Administrator values always win.** Seed definitions are defaults only.
- **Seed failure = startup failure.** The API does not listen on partial
  reference data; the error names the seed and the failing operation, with the
  innermost Postgres message (Drizzle wraps driver errors).
- **Concurrency:** one transaction holding `pg_advisory_xact_lock(4203117001)`
  with `SET LOCAL lock_timeout = '30s'`. Transaction-scoped rather than
  session-scoped so the lock is released on commit/rollback and cannot leak a
  pooled connection. Inserts also use `ON CONFLICT (key) DO NOTHING` as a
  second guard.
- **Single source of definitions:** `modules/seeding/seeds/system-parameters.seed.ts`.
  `scripts/seed-system-parameters.ts` is a thin CLI wrapper over `runSeeds()`.

## Startup Order (`apps/api/src/server.ts`)

`dotenv` + route imports -> `runSeeds()` -> start cron jobs -> `app.listen()`
(email verification stays in the listen callback, non-fatal).

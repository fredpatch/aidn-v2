# SESSION1-UX-1 - Applicant actions and operational next actions: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every action AIDN expects from the applicant is listed, ordered by the server, on the portal dashboard (« Actions requises »), in the dossier banner and in the phase summary; every admin next action says who must act and offers a button only to the role that can act.

**Architecture:** Pure `can…` / `expects…` predicates in `@aidn/shared` (with `expects ⇒ can`) are called by the write services (authorization) and by a new API module `applicant-actions` that loads a fixed set of batch rows and builds an ordered `ApplicantAction[]` (`GET /api/applicant/actions`). The portal renders that list as-is (wording keyed by action) on the dashboard, dossier banner and phase summaries; its phase builders become passive. The Demandes cockpit reuses the same row loader and builder to say when the applicant is awaited, and gains a typed `NextActionOwner` and an `OperationalState`, rendered by one admin `OperationalCallout`.

**Tech Stack:**

- API: Express, Drizzle 0.45, PostgreSQL, `node:test` via `tsx --test`.
- Shared: `packages/shared` (TypeScript, consumed through `dist/` - rebuild after every change).
- Front ends: React, Vite, TanStack Query, vitest and Testing Library (admin and portal).

**Spec:** `docs/superpowers/specs/2026-10-15-session1-ux-1-design.md`. Read it with this plan; it is the authority.

## Global Constraints

- The API is the source of truth for `ApplicantAction[]`: eligibility, order, anchor, `dueAt`, `urgent`, `count`, `variant`. The portal never sorts and never decides eligibility (D1).
- The portal owns all French action wording, keyed by `ApplicantActionKey`. The API sends no French text for applicant actions (D2). (Cockpit staff wording stays server-side, as today.)
- `ApplicantAction[]` contains only actions actually expected from the applicant, never passive waiting states.
- Predicates come in two levels: `can…` (the route accepts) and `expects…` (the action is shown); `expects ⇒ can`, pinned by a test.
- `formal_missing_documents` counts `isFormalDocumentMissing` rows - the exact rule of the M4 closure gate (`DOCUMENTS_INCOMPLETE`). All 11 slots are mandatory today; **do not invent optionality or applicability**.
- M4 pieces are actionable as soon as M4 opens; no letter-return gate (D4).
- Past unconfirmed meetings: MEET-1 rule kept - still listed while `canApplicantRespond`, `urgent` because overdue. **No expiry, no hiding.**
- Base priorities: `meeting_confirmation 10, payment_proof 20, document_correction 30, formal_letter 40, formal_missing_documents 50, preliminary_declaration 60, signed_meeting_report 80, certificate_collection 90`. `URGENCY_WINDOW_HOURS = 72` (code constant). Order: urgent first (by `dueAt`, then base), then non-urgent (by base, then `dueAt`, nulls last), then `requestReference`, then `id`.
- Dashboard meeting confirmation deep-links to `/dossiers/{requestId}#rendez-vous-{meetingId}` (D6). `MeetingsToConfirmBanner` and `ReportsToSignBanner` are deleted (D7).
- Admin `NextActionOwner = { kind: 'staff' | 'applicant' | 'external'; label: string; roles?: InternalRole[] }`; `staff.roles` copies the write route's `requireRole` list, `SU` included. `canAct` = staff owner ∩ session roles. No disabled buttons for another role's work.
- D11: payment presentation and expectation use `status === 'awaiting_proof'`; no migration, no data cleanup, `rejection_reason` untouched.
- Error codes, HTTP mappings and the `claimUploadAsset` replay order of every write service are unchanged.
- MEET-1 confirmation literals: outside `apps/api/src/modules/meetings/` and `shared/db/`, never compare `confirmationStatus` literals (`meeting-confirmation.literals.test.ts`); call `meeting-confirmation.ts` helpers.
- Out of scope: role dashboards / cockpit redesign, cockpit metrics, ACCOUNT-1, e-mail / notifications, migration.
- **Commits:** none per task. One commit after full validation (Task 9). Do not push.
- **Commands** (repo root):
  - `npm run build --workspace=packages/shared` after any change in `packages/shared` (apps import `dist/`).
  - `npm run test --workspace=apps/api -- --test-concurrency=1` (DB tests need `DATABASE_URL` on a migrated, disposable DB; they skip without it - never the dev DB from `apps/api/.env`).
  - `npm run test --workspace=apps/admin`, `npm run test --workspace=apps/portal`.
  - Single API file: `npx tsx --test --test-concurrency=1 apps/api/src/modules/<path>.test.ts` (from the repo root, with `DATABASE_URL` set for DB files). Single front-end file: `npx vitest run <path>` from `apps/portal` or `apps/admin`.

## Review Focus

1. **Cockpit hides the phase page from the DN when someone else must act.** Today « Traiter - … » links to the phase page; with an applicant / Finance owner the callout has no CTA, but the DN must still be able to open the phase page. Expected: a secondary « Consulter la phase » link (not a workflow CTA) whenever `nextActionHref` is set and `canAct` is false. Pinned in Task 7.
2. **Actions endpoint fails or is slow.** Expected: dashboard section shows a one-line retry; dossier banner and summaries fall back to passive wording; every section still renders its own controls. Pinned in Task 5 (panel) and Task 6 (dossier).
3. **Payment validated after an earlier rejection** (`status 'validated'`, `rejection_reason` still set). Expected: no `payment_proof` action, no « Nouvelle quittance requise » anywhere, passive state « Paiement validé ». Pinned in Task 3 (unit + DB) and Task 6 (builders).
4. **Same key on two dossiers / two meetings of one dossier.** Expected: two rows with two distinct links, ids unique, no merge. Pinned in Task 3 (unit) and Task 5 (panel).
5. **Existing portal tests start fetching `/applicant/actions`.** Any component using `useApplicantActions` inside a test without a seed would hit the network. Expected: `renderWithProviders` seeds `[]` for the actions key by default. Pinned in Task 5 step 1.

import type { InternalRole } from './statuses.js';

/** SESSION1-UX-1 - every action AIDN expects from the applicant. Only actions
 *  actually expected now - never a passive waiting state. */
export const APPLICANT_ACTION_KEYS = [
  'meeting_confirmation',
  'signed_meeting_report',
  'preliminary_declaration',
  'formal_letter',
  'formal_missing_documents',
  'payment_proof',
  'document_correction',
  'certificate_collection',
] as const;
export type ApplicantActionKey = (typeof APPLICANT_ACTION_KEYS)[number];
export type ApplicantActionPhase = 'M3' | 'M4' | 'M5' | 'M6' | 'M7';

/** Base priority, lower first. Keys below 80 block their phase. */
export const APPLICANT_ACTION_PRIORITY: Record<ApplicantActionKey, number> = {
  meeting_confirmation: 10, // an unconfirmed meeting cannot be held (MEETING_NOT_CONFIRMED)
  payment_proof: 20, // closure needs a validated payment (PAYMENT_NOT_VALIDATED)
  document_correction: 30, // DOCUMENTS_NOT_ALL_VALIDATED
  formal_letter: 40, // formal meeting and closure (LETTER_NOT_TRANSMITTED)
  formal_missing_documents: 50, // DOCUMENTS_INCOMPLETE
  preliminary_declaration: 60, // M3 closure
  signed_meeting_report: 80, // never blocks (SESSION1-MEET-2)
  certificate_collection: 90, // physical, final step
};

/** An action due within this many hours (or overdue) is urgent. Ordering only:
 *  no SLA, no business deadline. */
export const URGENCY_WINDOW_HOURS = 72;

export interface ApplicantAction {
  /** `${key}:${requestId}:${subjectId}` - unique in a response. */
  id: string;
  key: ApplicantActionKey;
  requestId: number;
  requestReference: string;
  phaseCode: ApplicantActionPhase;
  priority: number;
  urgent: boolean;
  /** Dossier page fragment without '#'. */
  anchor: string;
  dueAt: string | null;
  count?: number;
  variant?: 'after_rejection';
}

/** Admin - who must act next. */
export type OperationalState = 'action_required' | 'waiting' | 'information' | 'done' | 'blocked';

export interface NextActionOwner {
  kind: 'staff' | 'applicant' | 'external';
  label: string;
  /** staff only: exactly the requireRole(...) list of the route that performs the action. */
  roles?: InternalRole[];
}

// ── M3 declaration ─────────────────────────────────────────────────────────
interface DeclarationForm {
  madeAvailableAt: unknown | null;
  submittedFileUrl: string | null;
}
/** The route accepts a declaration (NOT_YET_AVAILABLE / DECLARATION_ALREADY_SUBMITTED). */
export function canApplicantSubmitDeclaration(form: DeclarationForm): boolean {
  return form.madeAvailableAt !== null && form.submittedFileUrl === null;
}
export function expectsPreliminaryDeclaration(
  form: DeclarationForm,
  m3: { status: string }
): boolean {
  return canApplicantSubmitDeclaration(form) && m3.status === 'open';
}

// ── M4 letter and pieces ───────────────────────────────────────────────────
export function canApplicantSubmitLetter(
  phase: { status: string },
  existingLetter: unknown | null
): boolean {
  return phase.status === 'open' && existingLetter === null;
}
export function expectsFormalLetter(
  phase: { status: string },
  existingLetter: unknown | null
): boolean {
  return canApplicantSubmitLetter(phase, existingLetter);
}

/** An M4 piece still expected from the applicant - the definition the closure
 *  gate (DOCUMENTS_INCOMPLETE) enforces. All 11 slots are mandatory today: any
 *  future optionality rule belongs here only. */
export function isFormalDocumentMissing(doc: { status: string }): boolean {
  return doc.status === 'missing';
}
export function missingFormalDocumentCount(docs: ReadonlyArray<{ status: string }>): number {
  return docs.filter(isFormalDocumentMissing).length;
}
export function canApplicantSubmitFormalDocument(
  phase: { status: string },
  doc: { status: string }
): boolean {
  return phase.status === 'open' && isFormalDocumentMissing(doc);
}
/** D4 - from the moment M4 opens, no letter-return gate. */
export function expectsFormalDocuments(
  phase: { status: string },
  docs: ReadonlyArray<{ status: string }>
): boolean {
  return phase.status === 'open' && missingFormalDocumentCount(docs) > 0;
}

// ── Payments (M5 / M6 / M7) ────────────────────────────────────────────────
interface PaymentState {
  status: string;
  invoiceFileUrl: string | null;
}
/** The route accepts a proof: a pending one may still be replaced. */
export function canApplicantUploadProof(payment: PaymentState): boolean {
  return payment.invoiceFileUrl !== null && payment.status !== 'validated';
}
/** D11 - expected only while awaiting a proof; rejection_reason never decides. */
export function expectsPaymentProof(payment: PaymentState): boolean {
  return payment.invoiceFileUrl !== null && payment.status === 'awaiting_proof';
}

// ── M5 corrections ─────────────────────────────────────────────────────────
export function canApplicantResubmit(evaluation: { verdict: string | null }): boolean {
  return evaluation.verdict === 'rejected' || evaluation.verdict === 'needs_correction';
}
export function expectsDocumentCorrection(
  m5: { status: string },
  evaluations: ReadonlyArray<{ verdict: string | null }>
): boolean {
  return m5.status === 'open' && evaluations.some(canApplicantResubmit);
}

// ── M7 collection (physical) ───────────────────────────────────────────────
export function expectsCertificateCollection(certificate: { status: string }): boolean {
  return certificate.status === 'notified';
}

import {

  URGENCY_WINDOW_HOURS,
  expectsCertificateCollection,
  expectsDocumentCorrection,
  expectsFormalDocuments,
  expectsFormalLetter,
  expectsPaymentProof,
  expectsPreliminaryDeclaration,
  missingFormalDocumentCount,
  type ApplicantAction,
  type ApplicantActionKey,
  type ApplicantActionPhase,
} from '@aidn/shared';
import {
  canApplicantRespond,
  canApplicantSubmitSignedReport,
  requiresApplicantConfirmation,
} from '../meetings/meeting-confirmation.js';
import { isDossierClosed } from '../requests/dossier-open.js';
import type { ApplicantActionRows } from './applicant-actions.rows.js';

export const ACTION_ANCHORS = {
  meeting: (meetingId: number) => `rendez-vous-${meetingId}`,
  signedReport: (meetingId: number) => `compte-rendu-${meetingId}`,
  declaration: 'declaration',
  letter: 'lettre',
  pieces: 'pieces',
  payment: (phaseCode: string) => `paiement-${phaseCode}`,
  corrections: 'corrections',
  collection: 'retrait',
} as const;

type Phase = ApplicantActionRows['phases'][number];

function action(
  key: ApplicantActionKey,
  phase: Phase,
  subjectId: number,
  anchor: string,
  now: Date,
  extra: { dueAt?: Date | null; count?: number; variant?: 'after_rejection' } = {}
): ApplicantAction {
  const due = extra.dueAt ?? null;
  return {
    id: `${key}:${phase.requestId}:${subjectId}`,
    key,
    requestId: phase.requestId,
    requestReference: phase.requestReference,
    phaseCode: phase.phaseCode as ApplicantActionPhase,
    priority: APPLICANT_ACTION_PRIORITY[key],
    urgent: due !== null && due.getTime() <= now.getTime() + URGENCY_WINDOW_HOURS * 3_600_000,
    anchor,
    dueAt: due ? due.toISOString() : null,
    ...(extra.count !== undefined ? { count: extra.count } : {}),
    ...(extra.variant ? { variant: extra.variant } : {}),
  };
}

export function buildApplicantActions(rows: ApplicantActionRows, now: Date): ApplicantAction[] {
  // The cockpit loads closed dossiers too (includeClosedDossiers): they never carry an action.
  const openPhases = rows.phases.filter((p) => !isDossierClosed(p.requestStatus));
  const phaseById = new Map(openPhases.map((p) => [p.id, p]));
  const phaseOf = (requestId: number, code: string) =>
    openPhases.find((p) => p.requestId === requestId && p.phaseCode === code);
  const out: ApplicantAction[] = [];

  for (const meeting of rows.meetings) {
    const phase = phaseById.get(meeting.phaseId);
    if (!phase || !requiresApplicantConfirmation(meeting.meetingType)) continue;
    // Rows are open dossiers only, hence dossierClosed = false.
    if (canApplicantRespond(meeting)) {
      out.push(
        action('meeting_confirmation', phase, meeting.id, ACTION_ANCHORS.meeting(meeting.id), now, {
          dueAt: meeting.scheduledAt,
        })
      );
    }
    if (canApplicantSubmitSignedReport(meeting, false)) {
      out.push(
        action(
          'signed_meeting_report',
          phase,
          meeting.id,
          ACTION_ANCHORS.signedReport(meeting.id),
          now
        )
      );
    }
  }
  for (const form of rows.forms) {
    const phase = phaseById.get(form.phaseId);
    if (phase && expectsPreliminaryDeclaration(form, phase)) {
      out.push(
        action('preliminary_declaration', phase, form.id, ACTION_ANCHORS.declaration, now, {
          dueAt: form.returnDeadline,
        })
      );
    }
  }
  for (const phase of openPhases.filter((p) => p.phaseCode === 'M4')) {
    const letter =
      rows.circuits.find(
        (c) => c.requestId === phase.requestId && c.entityType === 'formal_request_letter'
      ) ?? null;
    if (expectsFormalLetter(phase, letter))
      out.push(action('formal_letter', phase, phase.id, ACTION_ANCHORS.letter, now));
    const docs = rows.formalDocuments.filter((d) => d.phaseId === phase.id);
    if (expectsFormalDocuments(phase, docs)) {
      out.push(
        action('formal_missing_documents', phase, phase.id, ACTION_ANCHORS.pieces, now, {
          count: missingFormalDocumentCount(docs),
        })
      );
    }
  }
  for (const payment of rows.payments) {
    const phase = phaseById.get(payment.phaseId);
    if (phase && expectsPaymentProof(payment)) {
      out.push(
        action(
          'payment_proof',
          phase,
          payment.id,
          ACTION_ANCHORS.payment(phase.phaseCode),
          now,
          payment.rejectionReason ? { variant: 'after_rejection' } : {}
        )
      );
    }
  }
  for (const m5 of openPhases.filter((p) => p.phaseCode === 'M5')) {
    const evaluations = rows.evaluations.filter((e) => e.requestId === m5.requestId);
    if (!expectsDocumentCorrection(m5, evaluations)) continue;
    const toCorrect = evaluations.filter(canApplicantResubmit); // same rule as the resubmit route
    const deadlines = toCorrect
      .map((e) => e.correctionDeadline)
      .filter((d): d is Date => d !== null);
    const earliest = deadlines.length
      ? new Date(Math.min(...deadlines.map((d) => d.getTime())))
      : null;
    out.push(
      action('document_correction', m5, m5.id, ACTION_ANCHORS.corrections, now, {
        dueAt: earliest,
        count: toCorrect.length,
      })
    );
  }
  for (const certificate of rows.certificates) {
    const m7 = phaseOf(certificate.requestId, 'M7');
    if (m7 && expectsCertificateCollection(certificate)) {
      out.push(
        action('certificate_collection', m7, certificate.id, ACTION_ANCHORS.collection, now)
      );
    }
  }
  return orderApplicantActions(out);
}

const time = (iso: string | null) => (iso === null ? Number.POSITIVE_INFINITY : Date.parse(iso));

export function orderApplicantActions(actions: ApplicantAction[]): ApplicantAction[] {
  return [...actions].sort((a, b) => {
    if (a.urgent !== b.urgent) return a.urgent ? -1 : 1;
    const primary = a.urgent
      ? time(a.dueAt) - time(b.dueAt) || a.priority - b.priority
      : a.priority - b.priority || time(a.dueAt) - time(b.dueAt);
    return (
      primary || a.requestReference.localeCompare(b.requestReference) || a.id.localeCompare(b.id)
    );
  });
}

import { useEffect } from 'react';
/** Reached from an action link (#anchor): the target may mount after the navigation, so it scrolls itself into view. */
export function useHashScroll(anchor: string): void {
  useEffect(() => {
    if (window.location.hash === `#${anchor}`)

  }, [anchor]);
}

import type { InternalRole, NextActionOwner } from '@aidn/shared';
import { useAuth } from '../hooks/useAuth';
/** Display decision mirroring the route guard; the API still enforces it. */
export function canAct(
  owner: NextActionOwner | null | undefined,
  userRoles: readonly InternalRole[]
): boolean {
  return owner?.kind === 'staff' && (owner.roles ?? []).some((role) => userRoles.includes(role));
}
export function useCanAct(owner: NextActionOwner | null | undefined): boolean {
  const { user } = useAuth();
  return canAct(owner, user?.roles ?? []);
}

## Contradictions found while planning (ruled)

1. **Cockpit navigation vs. "CTA only when `canAct`"** (spec §7.5). Removing the « Traiter » link whenever someone else must act would stop the DN from opening the phase page of a dossier waiting on the applicant / Finance. Ruling: a navigation-only `secondary` link « Consulter la phase » is not a workflow CTA and is shown whenever `nextActionHref` is set and `canAct` is false. Keyboard « Entrée » in `RequestsPage` keeps navigating as today. Cost if wrong: one link to remove.
2. **Declaration guard order.** The spec says `submitEvaluation` "calls `canApplicantSubmitDeclaration(form)` for its two checks", but the availability check runs before `claimUploadAsset` and the "already submitted" check after it (replay semantics). Ruling: keep both positions; the availability check stays the explicit `!row.madeAvailableAt` test and the post-claim check calls `canApplicantSubmitDeclaration(row)`. Error codes and replay behaviour unchanged.
3. **Cockpit phase sees signed-report actions on other phases.** Spec §7.4 step 1 filters by the open phase; `signed_meeting_report` is also excluded explicitly (it never blocks). Applied as written.
4. **`document_correction` subject.** Evaluations hang off M4 documents; the action's phase is M5 (open M5 required). The subject id is the M5 phase id, as the spec says; corrections are found by `requestId`.
5. **Admin bundles have no applicant `actions[]`.** The admin helpers read `meeting.negotiation.confirmationStatus` for MEET-1 (spec §10 residual duplication); the API cockpit uses `isAwaitingDn` / the applicant-action builder.
